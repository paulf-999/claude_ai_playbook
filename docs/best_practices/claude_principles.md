# 🧭 Claude Principles

Six principles that underpin every practice in this playbook. Read these first — they explain the *why* behind the specific habits and rules.

| Principle | What it means |
|---|---|
| 🗺️ **Plan:** think it through before you start | Non-trivial work gets a plan reviewed before any file is touched. Catching a wrong direction costs one turn; undoing five files of work costs much more. |
| 🎯 **Context:** set the scene before you ask | Constraints, file paths, and desired outcome belong in the first prompt — not discovered through a series of corrections. The more Claude knows at the start, the less rework. |
| ✂️ **Focus:** ask for one thing at a time | Ask for exactly what you need, one change at a time. Broad requests produce broad changes that are hard to review and easy to get wrong. |
| 🔍 **Verify:** check the actual output, not the description | Claude describes intent; the file is the truth. Always verify the actual change before moving on — a confident summary can still be wrong. |
| 🛠️ **Automate:** build habits that save you time | Recurring workflows deserve a skill or hook, not a repeated prompt. Time spent building the library pays back on every future session. |
| 🧪 **Evaluate:** try it before you trust it | Before making Claude a regular part of a workflow, run a quick evaluation: test real examples, find the failure modes, and decide where human review is non-negotiable. See [Evaluating Claude for your workflows](ai_fluency.md). |
