# Claude config reset — v1 playbook baseline → v2 minimal

## Why reset?

Boris Cherny (author of Claude Code) recommends resetting your `~/.claude/` config every 6
months to prevent CLAUDE.md bloat. The v1 config had grown into a large composed file with
dozens of `@import` directives covering rules, style guides, agents, and process files. Over
time, every import adds to context cost and reduces signal-to-noise.

The reset applies [Andrej Karpathy's 4 principles](https://github.com/multica-ai/andrej-karpathy-skills/)
as the new baseline — start minimal, add back only what demonstrably improves behaviour.

---

## What was archived

All prior `~/.claude/` content was preserved in a versioned release directory:

```
~/.claude_releases/v1_playbook_baseline/
```

This includes all rules, style guides, agents, skills, hooks, process files, memory files,
and settings from the v1 playbook. Nothing was deleted — the archive is the rollback path.

---

## New structure

After the reset, `~/.claude/` contains:

```
~/.claude/
├── CLAUDE.md              # thin orchestration file — imports only
├── settings.json          # minimal settings: plan mode, auto-memory, git allow-list
├── memory/
│   └── MEMORY.md          # global memory index (auto-managed by Claude Code)
├── _rules/
│   ├── conventions.md     # ~/.claude/ directory naming conventions
│   └── file_standards.md  # authoring standards for files in _rules/
└── _docs/
    └── decisions/
        ├── CLAUDE.md      # rationale for CLAUDE.md structural decisions
        └── settings.json.md  # rationale for each settings.json entry
```

### Naming convention

Directories the user creates use an **underscore prefix** (`_rules/`, `_docs/`). Directories
auto-generated by Claude Code use no prefix (`memory/`, `sessions/`, `backups/`). This makes
it immediately clear at a glance which directories are owned by whom.

---

## What CLAUDE.md now imports

Three imports only:

1. `memory/MEMORY.md` — personal context first, so memories and corrections frame rule application
2. `_rules/conventions.md` — directory naming convention for `~/.claude/`
3. `_rules/file_standards.md` — authoring standards for files written to `_rules/`

Everything else from v1 (git rules, security rules, Jira style guide, etc.) was deliberately
omitted. Add back imports only when a gap is demonstrated across multiple sessions.

---

## How to reproduce the reset

See `src/sh/reset_claude_config.sh` — a shell script that captures the full sequence of
manual commands used to perform the v1 → v2 reset. Run it to set up an equivalent baseline
from scratch, or as a reference for the next scheduled reset.

---

## Rollback

To restore the v1 config:

```bash
cp -r ~/.claude_releases/v1_playbook_baseline/. ~/.claude/
```

This overwrites the v2 minimal config with the full v1 playbook content.
