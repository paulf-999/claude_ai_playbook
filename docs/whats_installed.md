# 📦 What's installed

> **Do not edit this file directly.** It is a managed index. See `src/claude/rules/managed_files.md`.

Last updated: 9th June 2026

`make install` copies the contents of `src/claude/` into `~/.claude/`. This document describes what each category of file does and links to the relevant index.

Claude Code loads `CLAUDE.md` on startup — it composes all rules, style guides, and process files via `@import` directives.

---

## 📄 Top-level files

| File | Purpose |
|------|---------|
| `CLAUDE.md` | 🧠 Root config loaded by Claude Code; imports all rules, process, and style files |
| `settings.json` | ⚙️ Team baseline Claude Code settings (permissions, MCP servers) |

## 🔄 Process

Session-conduct rules now live under [`src/claude/_rules/`](../src/claude/_rules/) (`02_claude_standards/` and `03_claude_reference/`).

Instructions that shape how Claude works within a session:
- the runtime environment declaration
- the planning requirement before non-trivial changes (including the plan catalogue)
- the structured session start/end checklist
- the permission model
- the task brief convention for lean sub-agent orchestration (see [`docs/reference/claude_config/orchestration.md`](reference/claude_config/orchestration.md))
- the draft file convention (`~/_drafts/`, organised by type)
- the sub-agent selection guidance — default agent, available sub-agents, and how to switch

## 📏 Rules

See [`src/claude/rules/README.md`](../src/claude/rules/README.md)

Hard constraints that Claude must follow in every session, covering:

- behaviour
- credit efficiency
- documentation updates (minimal diff, self-validation checklist, diff-first presentation)
- file hygiene
- git
- managed files (index files that must not be edited directly)
- MCP discipline
- security
- skill authoring standards
- testing
- transparency

**Proactive decision logging** (`rules/behaviour/decision_logging.md`) — Claude automatically logs non-obvious choices to memory as they are made, using a two-part grain test to keep signal-to-noise high. Contributor-relevant decisions are also written to `docs/decisions/<theme>/` in the repo and staged alongside the change that prompted them.

## 🔌 MCP servers

See [`docs/reference/claude_config/mcp/mcp_setup.md`](reference/claude_config/mcp/mcp_setup.md)

* MCP servers extend what Claude can access during a session.
* Core servers are always active; integration servers are disabled by default and enabled per session via `make enable_mcp` / `make disable_mcp`.

---

## 🔌 Plugins

See [`docs/reference/claude_config/plugins.md`](reference/claude_config/plugins.md) · **Install:** `make install_plugins`

* Claude Code plugins add skills, commands, and hooks directly to the CLI.
* Distinct from MCP servers, which connect Claude to external tools.

---

## 🪝 Hooks

See [`src/claude/hooks/README.md`](../src/claude/hooks/README.md)

**Install:** included in `make install`

* Shell and Python scripts wired to Claude Code lifecycle events via `settings.json`.
