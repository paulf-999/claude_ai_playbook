# ADF Reference — Page Header & Formatting

All `confluence_create_page` patterns use these header structure and formatting rules consistently.

---

## Standard ADF Page Header

Every generated page must include this header at the start of the ADF `content` array, in order.

### 1. Note panel — Claude Code

```json
{
  "type": "panel",
  "attrs": {"panelType": "note"},
  "content": [
    {"type": "paragraph", "content": [
      {"type": "text", "text": "Note: this page was generated by Claude Code."}
    ]}
  ]
}
```

### 2. Page Status — status badge

Colour mapping — always one badge, matching the selected status:

| Status | color value |
|---|---|
| Not started | `red` |
| In progress | `yellow` |
| Ready for review | `blue` |
| Complete | `green` |

```json
{
  "type": "paragraph",
  "content": [
    {"type": "text", "text": "Page Status", "marks": [{"type": "strong"}]},
    {"type": "text", "text": ": "},
    {
      "type": "status",
      "attrs": {
        "text": "<STATUS_LABEL>",
        "color": "<COLOR>",
        "style": "bold",
        "localId": "<uuid>"
      }
    }
  ]
}
```

### 3. Header metadata (one paragraph each)

```json
{"type": "paragraph", "content": [{"type": "text", "text": "Creator", "marks": [{"type": "strong"}]}, {"type": "text", "text": ": <name>"}]}
{"type": "paragraph", "content": [{"type": "text", "text": "Version", "marks": [{"type": "strong"}]}, {"type": "text", "text": ": 1.0"}]}
{"type": "paragraph", "content": [{"type": "text", "text": "Date Created", "marks": [{"type": "strong"}]}, {"type": "text", "text": ": <today's date>"}]}
```

### 4. Purpose — info panel

Draft the purpose statement as a single, brief, high-level sentence if the user has not provided one.

```json
{
  "type": "panel",
  "attrs": {"panelType": "info"},
  "content": [
    {"type": "paragraph", "content": [
      {"type": "text", "text": "The purpose of this page is to …"}
    ]}
  ]
}
```

### 5. Contents heading + TOC macro + rule

```json
{"type": "heading", "attrs": {"level": 1}, "content": [{"type": "text", "text": "📋 Contents"}]}

{
  "type": "extension",
  "attrs": {
    "extensionType": "com.atlassian.confluence.macro.core",
    "extensionKey": "toc",
    "parameters": {
      "macroParams": {
        "minLevel": {"value": "1"},
        "maxLevel": {"value": "2"},
        "exclude": {"value": "Contents"}
      }
    },
    "layout": "default"
  }
}

{"type": "rule"}
```

## Formatting Rules

Apply these rules consistently to every page body.

### Headings

- All level-1 section headings must include an emoji prefix.
- Standard emoji mapping:

| Section type | Emoji |
|---|---|
| Overview / Summary | 🔍 |
| How it works / Process / Steps | ⚙️ |
| Reference / Checks / Details | 📌 |
| Requirements / Criteria | 📋 |
| Background / Context | 📖 |
| Timeline | 🕐 |
| Actions / Next steps | ✅ |
| Risk / Assessment | ⚠️ |
| Recommendation / Idea | 💡 |
| Decision | 🏛️ |
| Blocked | 🚧 |

ADF: `{"type": "heading", "attrs": {"level": 1}, "content": [{"type": "text", "text": "🔍 Section Name"}]}`

### Status fields

- Must always use ADF `status` node — never plain text.
- Apply standard colour mapping (see header section above).

### Tables

- Include `"attrs": {"layout": "full-width", "isNumberColumnEnabled": false}` on all table nodes.
- Header cells use `tableHeader` (not `tableCell`), with bold text.
- Cells with multiple values use multiple `paragraph` nodes.
- Step cells must be numbered: `1. 📋 Step name`, `2. ✅ Next step`, etc.

### Panels

- `note` panel: disclaimers, callouts, system-generated notices
- `info` panel: purpose statements, contextual guidance
- `warning` panel: important warnings requiring user attention
- Content prefixed with "Important:" must be in a `note` panel

### Prerequisites

- Must appear under a dedicated `⚙️ Prerequisites` heading, not embedded in another section.

### Inline code

- Wrap component names, file paths, commands, technical identifiers in inline code marks: `"marks": [{"type": "code"}]`

### Bold labels

- Field labels (e.g. **Creator**, **Version**, **Date Created**) must be bold: `"marks": [{"type": "strong"}]`

### Rule dividers

- Place a `rule` node after every body section, including the last section.

### Lists

- Prefer `bulletList` over prose for multiple items.
- Use `orderedList` for sequential steps or ranked items.
- Keep bullet lists to maximum 5 items; group or restructure as table if needed.

### Alignment

- All block-level components default to left-aligned or full-width.
- Omit alignment attributes or set `"attrs": {"layout": "default"}` on code blocks.
