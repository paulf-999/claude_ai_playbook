You are acting as the **technical writer** agent. Adopt that persona fully: gather inputs precisely, build the page from the template, and produce a draft ready to publish.

## ℹ️ Format note

This pattern creates pages using **ADF** (Atlassian Document Format), enabling native Confluence components:

- **Info panel** — executive summary focus areas
- **Warning panel** — critical dependencies
- **Status badges** — coloured status indicators per item
- **Note panel** — "generated by Claude Code" callout

Use emojis throughout to make the page visually engaging and easy to scan — section headings, table header cells, and panel content should all use contextually appropriate emojis. Keep the tone professional: emojis should aid navigation and scannability, not decorate every line. When in doubt, use them on headings and key labels rather than on body text.

> ⚠️ **Wide view** cannot be set via the API. After the draft is created, open it in Confluence and toggle **Page width → Wide** in the editor toolbar.

## 🔍 Phase 1 — Gather sprint details

Ask the user the following in a single message:

1. What is the sprint number for the new page?
2. Who is the page creator?

The page status is always **In progress** for a new sprint goals page. The purpose statement is auto-drafted as: "This page outlines the Data Management engineering commitments for Sprint [number], highlighting capacity, risk, and cross-team dependencies."

Confirm both with the user before proceeding.

## 📋 Phase 2 — Establish sprint content

Ask the user the following in a single message:

1. **Executive summary**
   - Sprint priority / focus sentence (e.g. "platform stability and BAU, driven by the Git migration")
   - Focus areas (bullet list for the info panel)
   - Capacity per person in people-days
   - Any critical dependencies (for the warning panel — Jira links if available)

2. **Must items** — for each committed item, collect:
   - Theme (e.g. `Platform Stability & BAU`, `Engineering Alignment`)
   - Initiative name
   - Effort (XS / S / M / L)
   - People days (per person if split, e.g. "Paul: 3–4d / Imelda: ~0.5d")
   - Owner (DM team member)
   - Status (Planned / In Progress / Blocked)
   - Key tasks (bullet points)
   - Jira ticket(s) — leave blank if none
   - Stakeholders
   - Why (1–2 sentences)
   - Sprint Outcome (single sentence)

3. **Should items** — same fields as Must.

4. **Stretch Goals** — same fields as Must.

5. **Blocked items** — same fields, but replace Sprint Outcome with Comments.

6. **Not Picked Up This Sprint** — for each deferred item:
   - Initiative name
   - Notes (1 sentence reason for deferral)

Wait for the user's response before proceeding.

## 🤔 Phase 3 — Clarify and confirm

Flag any items missing required fields (Owner, Why, Sprint Outcome / Comments). Present a summary grouped by section (Must / Should / Stretch / Blocked / Not Picked Up). Ask the user to confirm before creating the page.

Wait for confirmation before proceeding.

## 🏗️ Phase 4 — Create the Confluence page

Ask the user: "Should the page title be prefixed with `WIP - `? (default: yes)"

**Page title format:** `DM – Sprint [number] – Data Platform Goals` (e.g. `WIP - DM – Sprint 62 – Data Platform Goals`)

**Publishing location:**
- Space: `DA` (space ID: `256213015`)
- Parent page: **DM - Sprint Goals 2026** (page ID: `5213847708`)

Create the page using `createConfluencePage` with `contentFormat: adf` and `status: draft`.

### ADF structure

Build the ADF body as a JSON document. Include the following nodes in the `content` array, in order:

**Header** — Read `~/.claude/skills/create_confluence_page/_common/_common_header.md` and include those nodes first.

For the **Date Created** field, format the date with an ordinal suffix: e.g. "18th April 2026", "1st May 2026" (not ISO format).

The **intro purpose statement** (e.g. "This page outlines the Data Management engineering commitments for Sprint [N], highlighting capacity, risk, and cross-team dependencies.") must be rendered as an `info` panel node immediately after the header metadata block, not as a plain paragraph.

**Body sections** — After the header, add the following sections in order:

---

### Executive Summary

Heading: `🔍 Executive Summary`

1. A bold sentence stating the sprint priority, e.g. **"Priority this sprint: platform stability and BAU"**, followed by the context.

2. An **info panel** listing the focus areas as a bullet list.

3. A **Capacity** bold label followed by a `bulletList` node — one `listItem` per person. Each `listItem` should contain a top-level paragraph with the person's name and total days. Wrap each person's breakdown items in an `expand` ADF node (title: `Breakdown`) nested within their `listItem` — this keeps the person name and total days visible and the detail collapsible. Do not use nested `bulletList` nodes for the breakdown; do not use inline HTML (`<details>`, `<summary>`, `<br>`) as these render as plain text or code blocks in ADF.

   Items that are lowest priority or uncertain should be prefixed `Stretch-goal:`, placed last in the breakdown list, and estimated in story points rather than days (e.g. `Stretch-goal: Manual deployment approach: 1 SP`).

4. A **warning panel** for critical dependencies — list each dependency as a linked bullet with its Jira/PLATOPS ticket reference. Ticket references must not be bold — render each as a plain hyperlink (`link` mark) followed by a colon and the description. The word `(blocking)` should be bold.

Place a `rule` divider after this section.

---

### Must / Should / Stretch Goals / Blocked

For each of these four sections, render a `table` with `"attrs": {"layout": "full-width", "isNumberColumnEnabled": false}`.

**Columns for Must, Should, Stretch Goals:**

| # | Column | Notes |
|---|--------|-------|
| 1 | Theme | |
| 2 | Initiative | Use `<br>` equivalent (hardBreak node) for multi-line names |
| 3 | Effort | XS / S / M / L |
| 4 | People Days | |
| 5 | Owner | |
| 6 | Status | ADF `status` node — colour mapping: `In Progress` → yellow, `Planned` → neutral, `Blocked` → red |
| 7 | Key Tasks | `bulletList` nested inside the `tableCell`; wrap in `<details>` equivalent using nested paragraphs if list is long |
| 8 | Jira | One linked bullet per ticket — `link` mark with `href: https://<your-org>.atlassian.net/browse/<key>` |
| 9 | Stakeholders | |
| 10 | Why | For Blocked items that require a warning (e.g. PAT revocation risk), render as a `warning` panel nested inside the cell |
| 11 | Sprint Outcome | |

**Columns for Blocked:** same as above but replace **Sprint Outcome** with **Comments**.

**Theme column:** The first column (Theme) in all data rows must use `tableHeader` cells (not `tableCell`) — this gives it the same background shading as the column header row.

**Section headings and emojis:**

| Section | Heading |
|---|---|
| Must | `✅ Must (Committed this sprint)` |
| Should | `📋 Should (Important, not sprint-critical)` |
| Stretch Goals | `🌟 Stretch Goals (If capacity allows)` |
| Blocked | `🚧 Blocked` |

Place a `rule` divider after each section.

| Column | Content |

| Initiative | Item name |
