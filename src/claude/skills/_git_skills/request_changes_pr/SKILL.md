## 📐 Scope gate

| Maturity | Allowed |
|---|---|
| **draft** | Happy path only. Log gaps as TODOs, do not solve them. |

See [`flow.md`](flow.md) for the full decision flow.

## 🔐 Pre-check

Run `gh auth status`. On failure, stop: *"This skill requires `gh` CLI authenticated to GitHub. Run `gh auth login` and try again."*

---

## 📍 Phase 1 — Identify the PR

Accept a full URL or PR number as `$ARGUMENTS`. Fall back to `gh pr view --json number,url` on the current branch. Extract `owner/repo` and PR number.

Run in parallel:
- `gh pr diff <number> --repo <owner/repo>`
- `gh pr view <number> --repo <owner/repo> --json commits --jq '.commits[-1].oid'`
- `gh api repos/<owner>/<repo>/pulls/<number>/reviews` — check for existing CHANGES_REQUESTED from the current user
- `gh api repos/<owner>/<repo> --jq '.permissions.push'` — stop with a clear message if false

**Diff size:** if the diff exceeds 500 lines, truncate to 500. Flag for Phase 3 confirmation and the review body.

**Existing review:** if a CHANGES_REQUESTED review from the current user is found, ask:
> "Existing CHANGES_REQUESTED review found (ID: \<id\>). Replace it? (y/n)"

Store the answer — if yes, the existing review is dismissed in Phase 4 before posting.

---

## 🔍 Phase 2 — Analyse

Use `Agent` with `subagent_type: code_reviewer`. Pass the full diff and instruct it to return only **Must** and **Should** fix issues anchored to a specific file path and line number. See [`agent_return_format.md`](agent_return_format.md) for the required return format.

When formatting findings, convert any `-` bullets from agent output to `*` bullets per [`comment_format.md`](comment_format.md).

**If no findings are returned**, stop: *"No Must/Should issues found — no review posted."*

---

## 💬 Phase 3 — Format and confirm

Format each finding using [`comment_format.md`](comment_format.md).

Ask: *"Add `_Generated by Claude_` to the top of each inline comment? (y/n)"*

If the diff was truncated, warn before showing the preview:
> "Note: diff truncated to 500 lines — findings cover visible changes only. Continue? (y/n)"

Show the full proposed review — overall body and each inline comment with file path, line, and body — then ask:
> "Post this as a CHANGES_REQUESTED review on PR #\<number\>? (y/n)"

If no, stop.

---

## 🚀 Phase 4 — Post

If replacing an existing review, dismiss it first:

```bash
echo '{"message":"Superseded by updated review"}' | \
  gh api repos/<owner>/<repo>/pulls/<number>/reviews/<id>/dismissals --method PUT --input -
```

Post via `gh api repos/<owner>/<repo>/pulls/<number>/reviews --method POST --input -`.

Payload: `commit_id` (latest SHA), `event: REQUEST_CHANGES`, `body` (one-sentence summary; append truncation note if diff was truncated), `comments` array of `{ path, line, side: "RIGHT", body }`.

Return the PR URL.
